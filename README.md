# PlateQ — Adaptive Malaysian ANPR Platform

PlateQ is a production-oriented browser ANPR/LPR system for Malaysian number plates, designed for Windows and macOS laptops running the latest Google Chrome or Microsoft Edge with an external USB webcam.

The scanner keeps the existing YOLOv8 Malaysian plate detector, PP-OCR recognition pipeline, ByteTrack lifecycle, runtime metrics, developer overlay, adaptive OCR scheduling, Malaysian validation, database matching, event logging, alerting, and dataset export flow. The current upgrade adds environment intelligence, plate-quality classification, desktop webcam management, and adaptive runtime configuration.

## Production Pipeline

```text
External USB Webcam
  -> Environment Intelligence Model
  -> Adaptive Configuration Engine
  -> YOLOv8 Malaysian Plate Detector
  -> ByteTrack Tracker Lifecycle
  -> Plate Quality Assessment Model
  -> Best Frame Buffer
  -> Perspective Correction
  -> Adaptive Image Enhancement
  -> PP-OCR
  -> Temporal Consensus
  -> Malaysian Plate Validation
  -> Database Matching
  -> Alert / Event Export
```

## Models

Place browser ONNX models in `public/models/`:

| Model | Path | Purpose |
| --- | --- | --- |
| YOLOv8 Malaysian plate detector | `public/models/plate-detector.onnx` | Detect plate bounding boxes |
| PP-OCR recognizer | `public/models/ppocr-rec.onnx` | Read plate text |
| PP-OCR dictionary | `public/models/ppocr-dict.txt` | OCR character dictionary |
| YOLOv8 environment classifier | `public/models/environment-classifier.onnx` | BDD100K-trained classifier for day/night/rain/fog/glare/highway/traffic/etc. |
| Environment classifier metadata | `public/models/environment-classifier.metadata.json` | Runtime class-order sidecar generated by training |
| YOLOv8 plate-quality classifier | `public/models/plate-quality-classifier.onnx` | Decide whether a crop should be sent to OCR |
| Plate-quality classifier metadata | `public/models/plate-quality-classifier.metadata.json` | Runtime class-order sidecar generated by training |

If the two new classifier files are not present, PlateQ keeps scanning with deterministic frame/crop heuristics and reports the fallback status in Developer Mode.

Environment model training:

```bash
npm run prepare:environment -- --bdd-root /path/to/bdd100k
npm run train:environment -- --data datasets/bdd100k-environment-cls
```

See `docs/environment-model-bdd100k.md` for the BDD100K mapping and YOLOv8 classification export workflow.

Plate-quality model training from reviewed Dataset Mode exports:

```bash
npm run prepare:quality -- --exports /path/to/track_dataset_export_*.json --clear
npm run train:quality -- --data datasets/plate-quality-cls
```

See `docs/plate-quality-model.md` for label definitions and the Dataset Mode conversion workflow.

## Adaptive Runtime

The adaptive configuration engine changes detector cadence, confidence gates, best-frame buffer length, preprocessing variants, OCR thresholds, consensus votes, and OCR queue behavior based on the current environment profile.

Environment classifier predictions must meet a confidence threshold before they change active scanner settings. Low-confidence predictions are still counted in runtime metrics, but the detector/OCR configuration stays on the last trusted profile.

Examples:

| Environment | Scanner Behavior |
| --- | --- |
| Day / Good condition | 10 FPS target, minimal preprocessing, standard consensus |
| Night / Low light / Tunnel | CLAHE/sharpen/inversion variants, longer buffers, higher consensus |
| Rain / Heavy rain | Higher crop-quality gate, longer track lifetime, stricter OCR confidence |
| Glare / Backlight | Reflection-tolerant quality gate and contrast-heavy preprocessing |
| Highway | Faster detector loop, shorter buffer, fewer OCR variants |
| Traffic / Parking | Highest-confidence OCR queue priority and higher concurrency |

## Desktop Webcam Manager

The scanner detects connected video inputs, classifies likely USB webcams versus built-in cameras, remembers the selected camera, supports camera refresh/switching, prefers `1920x1080 @ 30 FPS`, falls back to `1280x720`, and automatically attempts reconnect if a webcam stream ends.

The scanner UI shows camera name, resolution, FPS, current environment, backend, system health, detector FPS, OCR queue, crop quality, current camera, Developer Mode, and Dataset Mode.

## Dataset Mode

Dataset Mode records browser-safe samples with:

- original frame
- plate crop
- environment class and confidence
- quality class and confidence
- OCR result and confidence
- detector confidence
- track confidence
- timestamp
- camera metadata

Export produces YOLO, OCR, and classification dataset manifests in one JSON payload for later retraining/export tooling.
